# YouTube Playlist Summary Extractor

Стартовый комплект для автономного AI-агента, который превращает YouTube-плейлист в структурированную базу знаний в Markdown. Учитывает обновления YouTube, актуален на июнь 2026 года. Радикально экономит траффик. 

---

## Что это

Набор из трёх файлов, которые дают AI-агенту всё необходимое для автономной работы:

- **`CLAUDE.md`** — операционный протокол: что делать, в каком порядке, как обрабатывать ошибки
- **`README.md`** — этот файл: объяснение для человека
- **`setting.json`** — разрешения для агента (что ему можно делать без подтверждений)

---

## Задача, которую решает этот комплект

Дать AI-агенту ссылку на YouTube-плейлист и диапазон видео — получить папку с Markdown-файлами, где каждый файл содержит:

- метаданные видео (название, URL, длительность)
- конспект (краткое изложение содержания)
- ключевые тезисы (5–8 bullet points)
- фрагменты транскрипта из 5 точек видео
- примечания (длина транскрипта, особенности)

Плюс финальный индекс-файл со сводной таблицей по всем видео.

---

## Почему это полезно

YouTube-курсы плохо переиспользуются:
- видео неудобно просматривать повторно
- нет поиска по содержанию
- нет структурированных заметок
- знания «заперты» внутри платформы

Этот workflow превращает видеокурс в текстовую базу знаний, которую можно читать, искать, конспектировать, скармливать RAG-системам или просто открыть через год и быстро вспомнить суть.

---

## Как запустить

1. Скопируйте `CLAUDE.md` и `setting.json` в рабочую папку проекта.
2. Подключите папку к Cowork (или Claude Code).
3. Откройте Chrome с Claude in Chrome extension.
4. Скажите агенту:

   > Вот плейлист: [URL]. Нужны конспекты видео с [N] по [M]. Сложи в папку [PATH].

5. Агент сделает всё сам и вернётся с результатом.

## Ключевые технические решения

### Почему транскрипт через DOM, а не API?

YouTube встраивает URL транскрипта в `ytInitialPlayerResponse` — но он содержит сессионные токены, которые истекают. Попытка сделать `fetch()` внутри страницы возвращает пустой ответ. DOM-панель (кнопка «Показать текст видео») стабильно работает.

### Почему 5 выборок по 200 символов вместо полного текста?

JS-инструмент обрезает отображение результатов примерно на 1500 символах. Транскрипт видео — от 25 000 до 170 000 символов. Пять выборок по 200 символов из равномерно распределённых точек (0%, 20%, 40%, 60%, 80%) дают полный охват видео и укладываются в один вызов без обрезки.

### Почему Python для записи файлов?

Bash heredoc ломается на кириллице и символах вроде `"` и `$`. Python с `encoding="utf-8"` пишет файлы правильно всегда.

## Ограничения

- Зависит от UI YouTube — если интерфейс меняется, selector'ы могут сломаться
- Автоматические транскрипты бывают только на русском/английском (не у всех каналов)
- Очень длинные видео (3+ часа) дают транскрипты по 150 000+ символов — выборочный подход работает, но покрытие снижается
- Не работает с видео без транскрипта (некоторые прямые эфиры, видео с ручными субтитрами)

## Дополнительно

Хочешь улучшить:
- **Полный транскрипт** — измени подход: запиши транскрипт в hidden `<pre>` в DOM, читай через `get_page_text`
- **Несколько плейлистов** — добавь таблицу курсов в `CLAUDE.md`
- **Экспорт в другие форматы** — добавь шаг с pptx/docx skills
